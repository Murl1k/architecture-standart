### <a name="_b7urdng99y53"></a>**Название задачи:** STD-ADR2 передача ставок в кол-центры

### <a name="_hjk0fkfyohdk"></a>**Автор:** архитектор команды цифровой трансформации

### <a name="_uanumrh8zrui"></a>**Дата:** 11.10.2026

### <a name="_3bfxc9a45514"></a>**Функциональные требования**

решение дополняет STD-ADR1 из Task3: ставки ведутся в справочнике ставок АБС и публикуются в kafka

|   1   | ставки в системе кол-центра и в папке партнера обновляются не позже 15 минут после публикации в АБС, срок нужно согласовать с бизнесом |

|   4   | партнер получает ставки только файлами, вызывать api банка он не может                                                                 |

### <a name="_qmphm5d6rvi3"></a>**Решение**

диаграммы:

- [диаграмма контекста](c4-context.png), исходник [c4-context.puml](c4-context.puml)
- [диаграмма компонентов](c4-components.png), исходник [c4-components.puml](c4-components.puml)

основные решения:

1. источник ставок не меняется: справочник ставок в АБС и публикатор ставок в сервисе интеграции депозитов из STD-ADR1, к топику ставок в kafka подключаются еще два получателя (8)
2. в системе кол-центра появляется сервис ставок на java spring boot: приемник читает топик, хранилище держит последнюю версию ставок в базе postgresql системы, api отдает их интерфейсу оператора на react.js; кол-центр работает с копией ставок и не обращается к АБС (1, 2, 3, 7)
3. в сервисе интеграции депозитов появляются формирователь файла и sftp-клиент: после каждой публикации собирается csv с общими ставками и датой актуальности и кладется в папку партнера на sftp-сервере банка (1, 4, 5)
4. sftp-сервер разворачивает IT-отдел в сегменте сети для внешних подключений: доступ партнера по ключу, только к своей папке и с разрешенных адресов (6)

какие команды участвуют:

- команда АБС: формирователь файла и sftp-клиент в сервисе интеграции депозитов, сервис ставок и раздел ставок в системе кол-центра
- IT-отдел: sftp-сервер, сетевой доступ партнера, мониторинг доставки файла
- партнерский кол-центр: загрузка файла в свою систему

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

- система кол-центра запрашивает ставки по rest api сервиса интеграции депозитов: отклонено, нужен опрос по расписанию и отдельная нагрузка на сервис интеграции, а клиент kafka в системе кол-центра уже есть после STD-ADR1
- оставить рассылку xls-файлов по почте, как сейчас: отклонено, это ручной процесс без контроля доставки, ставки в кол-центрах разойдутся с сайтом и интернет-банком

**Недостатки, ограничения, риски**

- партнер забирает файл по своему расписанию, его ставки могут отставать от банка до следующей загрузки; в файле есть дата актуальности
- sftp-сервер новая точка входа извне: нужны контроль доступа, журналирование и мониторинг
- система кол-центра на платформе подрядчика, сервис ставок нужно согласовать с подрядчиком, чтобы обновления платформы его не сломали
- нагрузка на команду АБС растет: к работам STD-ADR1 добавляются сервис ставок в системе кол-центра и выгрузка для партнера
