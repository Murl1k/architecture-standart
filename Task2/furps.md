архитектурно значимые требования собраны в разделе +R, в разделах R и P они отмечены в комментарии

| Код  | Требования                                                                                                                                         | Комментарий                                                                                                                                |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| F    | Функциональные (Functionality)                                                                                                                     |                                                                                                                                            |
| F1   | на сайте клиент видит список доступных депозитов с актуальными ставками                                                                            |                                                                                                                                            |
| F2   | на сайте клиент подает заявку на депозит, указав ф. и. о. и номер телефона                                                                         |                                                                                                                                            |
| F3   | заявка с сайта попадает в систему кол-центра, менеджер кол-центра изучает ее, звонит клиенту и может предложить особые условия                     |                                                                                                                                            |
| F4   | после звонка новый клиент приходит в отделение для идентификации                                                                                   |                                                                                                                                            |
| F5   | в интернет-банке клиент видит список доступных депозитов с актуальными ставками и свои персональные ставки                                         |                                                                                                                                            |
| F6   | в интернет-банке клиент подает заявку на депозит, указав счет и сумму                                                                              | так же оформляется накопительный счет                                                                                                      |
| F7   | заявка в интернет-банке подтверждается кодом из СМС                                                                                                |                                                                                                                                            |
| F8   | в MVP заявку из интернет-банка обрабатывает менеджер бэк-офиса депозитов: подтверждает ставку и условия депозита в АБС                             |                                                                                                                                            |
| F9   | клиент получает СМС после подтверждения ставки и после открытия депозита                                                                           |                                                                                                                                            |
| F10  | ставки по депозитам ведутся в информационной системе вместо xls-файлов, с ними работают бэк-офис депозитов и бэк-офис кредитов                     |                                                                                                                                            |
| F11  | согласование ставки по заявке, в том числе специальной ставки, проходит в той же системе, без писем между сотрудниками                             |                                                                                                                                            |
| F12  | сотрудники депозитов и сотрудники кредитов не видят данные друг друга                                                                              |                                                                                                                                            |
| F13  | клиент видит статус своей заявки в интернет-банке                                                                                                  | дополнительное требование: без статуса клиенты будут звонить в кол-центр                                                                   |
| U    | Удобство использования (Usability)                                                                                                                 |                                                                                                                                            |
| U1   | сайт и интернет-банк следуют системе дизайна банка: привычные цвета и брендированные элементы                                                      |                                                                                                                                            |
| U2   | заявка оформляется за несколько шагов: выбрать депозит, указать счет и сумму, ввести код из СМС                                                    |                                                                                                                                            |
| R    | Надёжность (Reliability)                                                                                                                           |                                                                                                                                            |
| R1   | сервисы работают 24/7 и доступны в 99,9% случаев                                                                                                   | архитектурно значимое                                                                                                                      |
| R2   | при сбое в ЦОД сервисы интернет-банка остаются доступными и выдерживают требуемую нагрузку                                                         | архитектурно значимое                                                                                                                      |
| R3   | онлайн-заявки не ставят под угрозу работу АБС                                                                                                      | архитектурно значимое: база данных АБС уже перегружена                                                                                     |
| R4   | принятая заявка не теряется, если АБС или система кол-центра временно недоступны, и обрабатывается после восстановления                            | дополнительное требование, архитектурно значимое: следует из R3, заявки нельзя передавать в АБС синхронно                                  |
| P    | Производительность (Performance)                                                                                                                   |                                                                                                                                            |
| P1   | отклик по всем операциям с депозитами на сайте и в интернет-банке занимает миллисекунды                                                            | архитектурно значимое: ориентир до 500 мс, точное значение нужно согласовать с бизнесом                                                    |
| P2   | справочные данные при проведении платежей в интернет-банке загружаются быстрее секунды                                                             |                                                                                                                                            |
| P3   | новые компоненты масштабируются горизонтально, запросы равномерно распределяются между серверами, приложениями и ЦОД                               | архитектурно значимое                                                                                                                      |
| S    | Поддерживаемость (Supportability)                                                                                                                  |                                                                                                                                            |
| S1   | для новых сервисов и интеграций готовится документация для дальнейшего расширения системы: описание архитектуры и спецификации api                 |                                                                                                                                            |
| S2   | новые интеграции проверяются интеграционными тестами со смежными системами: АБС, системой кол-центра и СМС-шлюзом                                  | дополнительное требование: в процессе участвуют системы разных команд и подрядчиков                                                        |
| +R   | + Ограничения (Restrictions)                                                                                                                       |                                                                                                                                            |
| +R1  | при доработках используются технологии, которые уже есть в банке: ms sql и oracle для баз данных, .net, java, php и react.js для разработки        | новые технологии допустимы, если они совместимы с существующими платформами и сотрудники знают их хотя бы на уровне языка программирования |
| +R2  | для очередей сообщений используется kafka                                                                                                          | текущая платформа интернет-банка, asp.net mvc 4.5 на .net framework 4.5, с kafka несовместима                                              |
| +R3  | интернет-банк в новом процессе не работает напрямую с api и базой данных АБС                                                                       | база данных АБС перегружена, R3                                                                                                            |
| +R4  | АБС масштабируется только вертикально                                                                                                              |                                                                                                                                            |
| +R5  | функционал открытия депозитов в интернет-банке выносится в отдельные сервисы, это первый шаг перевода интернет-банка на микросервисную архитектуру | интернет-банк монолит на платформе подрядчика                                                                                              |
| +R6  | СМС-подтверждение заявки делает команда банка без доработки ядра интернет-банка                                                                    | функционал СМС реализован в ядре, его доработка требует подрядчика                                                                         |
| +R7  | ставки по депозитам и согласование ставки по заявке реализуются в АБС                                                                              | в АБС уже работают бэк-офисы депозитов и кредитов                                                                                          |
| +R8  | данные между клиентом, сайтом, интернет-банком и новыми сервисами передаются только по зашифрованному каналу (https, tls)                          |                                                                                                                                            |
| +R9  | СМС клиентам отправляются через СМС-шлюз телеком-оператора                                                                                         |                                                                                                                                            |
| +R10 | доработки системы кол-центра делают специалисты команды АБС с опытом java                                                                          | стек системы java spring boot, react.js и postgresql                                                                                       |
| +R11 | интернет-банк развернут в одном ЦОД на одной группе серверов, резервный ЦОД используется только при сбое                                           | текущее состояние, ограничивает выполнение R1 и R2; в MVP веб-приложение переводится в два ЦОД (Task3)                                     |
